 METHOD C - Structural equivalence of residual_mean / residual_var
 Applied to: residual_mean, residual_var

   Why not a row-by-row numerical comparison:
     The C firmware pushes the internal float32 residual into its
     window buffer; the CSV 'residual' column is that value rounded
     to %.3f. Combined with 50Hz decimation, the C window contents
     cannot be reconstructed from the CSV. A row-by-row mean/var
     comparison is therefore not well-defined on this dataset.

   Equivalence argument (by construction):
     1. kalman_filter.c kf_get_residual_stats computes
           mean = sum / W
           var  = sq_sum / W - mean*mean
        which is identical to the Python reference formula
        (np.mean / np.var, E[r^2]-E[r]^2 form).
     2. The residual feeding the window is itself verified:
        METHOD A confirms its inputs (x_pred via kf_estimate),
        METHOD B confirms residual = tof - prev_estimate.
     3. Same input sequence + identical function => identical
        output. residual_mean / residual_var equivalence FOLLOWS
        from METHOD A + METHOD B; it needs no separate numerical
        row comparison.

   Verdict: CONFIRMED BY CONSTRUCTION - formula match verified
            against kalman_filter.c; numerical equivalence follows
            from METHOD A + METHOD B.
